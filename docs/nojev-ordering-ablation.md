# No-Jev ordering ablation: 1,024-goal reproduction

This branch compares the published `LeanHammerComparison.cpu` outcomes with
three no-Jev ordering results on the same 1,024 intermediate Mathlib goals:

1. **Given order:** retain the candidate order generated by the search.
2. **Random:** seeded candidate permutation, demoting states already offered in
   the same goal behind fresh states.
3. **Hybrid:** run given order first, then run the random-norepeat fallback only
   for given-order misses. The resulting map covers all 1,024 sites.

The full random arm is run on all 1,024 sites and reported independently. The
hybrid's second pass is a separate, filtered run, so the scorer can compare its
outcomes against the standalone random results on those same missed sites.
The hybrid result uses its own fallback outcomes, not an assumption that two
separate timed trials must agree.

Jev proof-state ranking is disabled for all three controls. Premise selection,
proof search, the `LeanHammerComparison.cpu` method, goal deadline and tactic
configuration remain the published settings. The runner's `--mock` flag here
disables API ranking; the patched `NOJEV_RANKER=random-norepeat` mode still runs
the real Lean tactic and independently replays every proof. No Jev key or Jev
service is used.

## Resource boundary and concurrency

Use Linux cgroup v2 with a hard 16 GiB memory maximum and zero swap. The arm
runner verifies `memory.max=17179869184` and `memory.swap.max=0` before starting
and omits `--external-memory-limit`; the CLI records the observed cgroup. A
declaration that a process is externally managed is not a resource limit.

The batches inside each arm run in order, one at a time. Given-order and the
standalone random arm may run at the same time in separate capped processes;
the hybrid fallback starts after given-order finishes. Use separate Linux
checkouts for overlapping arms so their Lake build caches and outputs do not
race. This whole-arm concurrency differs from the upstream guide's instruction
to run no concurrent heavy job. It is disclosed in the result metadata.
Elapsed times are not compared unless a separate sequential/concurrent check
shows that timeouts and errors remain stable.

## Setup

Follow the upstream [confirmation reproduction guide](reproducing-confirmation.md)
for Linux prerequisites and native engines. Keep the pinned Lake manifest. Run
setup inside the same 16 GiB zero-swap cgroup used for later work. Install
`unzip` first: the pinned cvc5 and Lean-auto packages use it to unpack their
platform release archives. Starting from the repository root:

```sh
cd integrations/leanhammer
lake exe cache get
cd ../..
bash scripts/apply_nojev_ranker_patch.sh
cd integrations/leanhammer
lake build LeanHammerComparison
cd ../..
python3 -m pip install --no-deps ./integrations/leanhammer/.lake/packages/jevselector
```

The patch script checks the pinned JevHammer dependency revision before changing
only its `Ranker.lean`. The given-order control leaves the stock offline ranker
unchanged. Do not edit the identically named repository-root package copy.

Prepare a fresh selector artifact, excluding the published holdouts:

```sh
python3 -m jevselector prepare \
  --project integrations/leanhammer --modules Mathlib --scope Mathlib \
  --catalog public-constants \
  --exclude datasets/full-leanhammer-confirmation-v1/holdouts.json \
  --threads 2 --memory-limit 16000000000 --output artifacts/confirmation
```

The ranker patch changes project identity. Rediscover and re-admit the cohort
without running proof trials, then freeze it into a new plan. Do not overwrite
the checked-in dataset:

```sh
python3 -m jevhammer_benchmark discover \
  --project integrations/leanhammer \
  --modules-file datasets/full-leanhammer-confirmation-v1/modules.json \
  --exclude datasets/full-leanhammer-confirmation-v1/exclusions.json \
  --import LeanHammerComparison --count 1024 --max-per-declaration 1 \
  --seed 20260921 --threads 8 --memory-limit 16000000000 \
  --output runs/confirmation-discovery
python3 scripts/admit_complete_discovery.py \
  runs/confirmation-discovery \
  datasets/full-leanhammer-confirmation-v1/exclusions.json \
  runs/confirmation-admitted
mkdir -p runs/confirmation-plan
cp datasets/full-leanhammer-confirmation-v1/{recipe,modules,exclusions}.json \
  runs/confirmation-plan/
python3 scripts/freeze_confirmation_dataset.py \
  runs/confirmation-admitted/dataset.json \
  datasets/mathlib-broad-v1/holdouts.json runs/confirmation-plan
python3 scripts/check_nojev_cohort.py \
  datasets/full-leanhammer-confirmation-v1 runs/confirmation-plan
```

The last command must confirm the same full `sites`, `sources`, and `imports`,
with the six disjoint batches covering the same 1,024 sites. Stop if it fails.
The selector index must exist at `artifacts/confirmation/index.json` before
running an arm.

## Run the arms

The upstream project guide shows eight-way batch fan-out for its larger study.
This ablation keeps each arm sequential. In independent Linux checkouts, launch
these two commands in separate 16 GiB zero-swap cgroups if whole-arm concurrency
is desired:

```sh
bash scripts/run_nojev_arm.sh given \
  runs/confirmation-plan runs/nojev/given
```

```sh
bash scripts/run_nojev_arm.sh random \
  runs/confirmation-plan runs/nojev/random
```

The runner executes batches 0 through 5 in order and refuses to overwrite an
existing run directory. It clears `TYPESAFE_API_KEY`, applies the verified
cgroup boundary, and retains logs and raw ranker traces under the ignored local
`runs/` directory.

After given order completes, create six hybrid fallback datasets. Each one
changes only `sites`, retaining every given-order miss and nothing else:

```sh
mkdir -p runs/hybrid-plan
for batch in 0 1 2 3 4 5; do
  python3 scripts/filter_nojev_misses.py \
    "runs/confirmation-plan/batch-$batch.json" \
    "runs/nojev/given/batch-$batch/trials.jsonl" \
    "runs/hybrid-plan/batch-$batch.json"
done
bash scripts/run_nojev_arm.sh hybrid-fallback \
  runs/hybrid-plan runs/nojev/hybrid-fallback
```

The hybrid fallback is serial across its six filtered datasets. Modules with no
remaining sites are skipped by the benchmark runner. If an arm is incomplete,
preserve all outputs and report it as incomplete; do not selectively retry or
replace goals.

## Score and publish

The scorer requires all three run directories to be complete, independently
replayed, and recorded under the actual cgroup limit. It requires a full
1,024-site given-order and random arm plus a fallback record for exactly every
given-order miss. It reports full-cohort outcomes and the 652-site subset where
Jev made a state-ranking call. It also reports random-full versus fallback
outcome flips and the union implied by the two full arms.

```sh
python3 scripts/score_nojev_ablation.py \
  --plan runs/confirmation-plan \
  --jev docs/full-leanhammer-confirmation-v1-trials.jsonl \
  --given 'runs/nojev/given/batch-*/trials.jsonl' \
  --random 'runs/nojev/random/batch-*/trials.jsonl' \
  --fallback 'runs/nojev/hybrid-fallback/batch-*/trials.jsonl' \
  --random-stats runs/nojev/random/ranker-stats.jsonl \
  --fallback-stats runs/nojev/hybrid-fallback/ranker-stats.jsonl \
  --output docs/nojev-ordering-ablation-results.json \
  --trials-output docs/nojev-ordering-ablation-trials.jsonl
```

The published per-site file contains only public goal identifiers and outcome
booleans. Keep raw run manifests, logs, ranker traces, credentials, and machine
paths local. Report the actual counts and protocol deviation; the previously
published expected values (69 given, 63 random, and 89 for the union within the
652 Jev-asked goals) are not results for this reproduction.
